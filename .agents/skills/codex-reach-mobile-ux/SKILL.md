# Codex Reach 移动端交互

本 skill 按 Codex Reach 的使用场景适配 enhance-mobile-native-feel，支持在已有应用上持续改进手机操作流程。

## 项目依据

进入当前仓库的 AGENTS.md 和 docs/产品规格.md，按本次涉及功能读取有效规则。涉及方案取舍时查看 docs/决策记录.md。用户当次明确决定优先，版本、支持系统和已实现状态以现场文件为准。

项目使用 H5、TypeScript、Capacitor Android 与 Rust 服务。选型按已有依赖和真实 API 能力决定。Android 构建与模拟器验证沿用项目 CI，用户负责最终手机验收。

## 设计与审查方法

- 从本次操作的入口、主要任务、完成反馈和退出位置理解页面，结合用户截图与实际渲染检查信息密度、操作距离、滚动范围
- 对输入、上传和异步结果，明确所属草稿、对话与请求，以及切页、关闭、失败、重试后的状态
- 先形成能走通的操作流程，再调整字号、间距、图标和动效。导航栏、震动、主题和依赖按已确认需求选择
- 用户要求示意图时，产出真正的图形界面。可用 HTML/CSS 渲染为图片或图像工具制作，图中使用真实长度的合成内容，并标注方案示意
- 方案阶段给出设计和待验证能力。实现阶段沿实际入口完成变更，并按涉及范围检查代码、运行效果和手机交互

## 关键检查

### 阅读与操作密度

主要内容优先占据屏幕。路径、元数据和低频操作放入详情。状态图标与文字说明各自表达明确含义，运行、等待、未读与置顶分别使用有依据的数据。

Android 主要触摸目标以 48dp 为设计目标，实际结合 WebView 缩放测量。紧凑列表仍有足够点击范围。图标有可访问名称，系统字体放大后内容和操作仍可达。

### 输入、附件与键盘

输入区与附件摘要设置高度边界。普通输入到上限后内部滚动，原位展开发生于用户操作。展开、收起、键盘变化和屏幕旋转后保留草稿与光标，发送入口可达。

附件任务归属于原草稿。关闭面板后继续接收上传结果，逐项显示就绪、失败或中断。移除草稿引用和清理电脑文件分别处理。结果未知时先确定操作是否已完成，再决定重试，并区分上传结果与消息投递回执。

### 滚动、手势与退出

聊天记录、附件管理和阅读面板明确各自的滚动容器，弹层打开后背景保持位置。列表下拉刷新、列表长按管理、正文长按选字分别处理。手势操作提供可见的按钮或菜单入口。

系统返回结合键盘、当前弹层和页面历史处理。关闭图标与背景点击的含义一致，关闭后恢复原焦点和阅读位置。审批决定只由对应审批动作提交。

### 网页与电脑文件阅读

链接按网页 URL、电脑路径和其他协议识别，交给相应打开入口。半屏、展开和关闭遵循产品规格。

电脑 HTML 连同相对图片、样式和脚本一起阅读。预览内容运行在独立的阅读环境，电脑访问凭据由原生层或服务端持有。资源请求限制在此次授权的文档范围内，正文中的外链继续走统一入口。

文本、Markdown、图片和 PDF 根据格式提供适合的阅读方式。体积、加载进度和失败说明帮助用户判断，缓存与清理沿项目确认规则。

### 手机与桌面语义

新建与已有对话复用输入区和上下文选择流程，草稿按新建状态及具体对话独立保存。Skill 有效性按当前工作目录检查。模型与深度的生效时点、执行中追加、审批策略和桌面读状态均依据已核实接口。

`@` 候选的类型与行为遵循产品规格，文件和对话引用保留稳定标识与可读名称。引用的显示、草稿恢复及发送后的上下文读取一起验证，引用目标与消息发送目标分别保存。

文件传输压缩以解压后的字节一致为验收条件，分别测量传输量、端侧耗时和内存开销。

## 验证与交付

按本次改动选择场景，包括长标题、多附件、长输入、加载或失败状态、键盘、系统返回、前后台切换及大字体。优先检查本次缺陷能够复现的入口。

浏览器验证用于布局和网页逻辑，Android 验证用于真实触摸、键盘、安全区、原生插件和返回行为。按项目要求记录已执行的检查及仍待手机验证的部分。

交付描述本次改变的行为、依据和结果。示意图标注为设计方案，测试截图标注对应环境。
