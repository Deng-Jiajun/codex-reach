# Codex Reach

通过 Android 手机访问 Windows 电脑上正在运行的 Codex。采用 Rust 本地服务、H5 界面、Capacitor Android 和原生 SQLite，GitHub Actions 构建 Android APK 与 Windows 服务包。

项目协作与需求记录见 [协作入口](AGENTS.md)、[产品规格](docs/产品规格.md) 和 [决策记录](docs/决策记录.md)。

当前版本为 `0.6.0-preview`，支持 Android 13 及以上。固定签名 APK 与同版 Windows 服务包已生成，本次升级需要同时更新手机 APK 和电脑服务。

当前版本提供以下操作。

- 按项目筛选和搜索已加载的对话，在列表「⋯」切换日期、项目或状态分组，置顶优先并使用单行条目
- 通过列表长按和对话「⋯」改名、置顶、切换已读状态、归档恢复或确认永久删除
- 分页阅读 Markdown、正文图片、紧凑选段引用与过程记录，复制消息和代码，在已加载内容中查找并继续读取历史
- 新建和已有对话使用「＋」添加图片、文件，通过 `@` 选择 Skill、项目文件和对话引用，分别保留草稿
- 为下一轮选择模型、思考深度及可用的审批策略，执行中选择立即追加或排队到下一轮
- 电脑持久保存待发队列，支持查看、编辑、取消和查询不确定的结果
- 半屏阅读网页、电脑 HTML、Markdown、文本／代码、图片和 PDF，展开全屏或保存原文件到手机
- 分块上传并查询结果，新文件按电脑接收日期保存，同名追加序号，关闭面板后结果仍归原草稿
- 处理命令、文件、权限审批、用户问题和标准 MCP 表单，停止当前轮次或编辑最近一条原生用户消息
- 在 Android SQLite 中缓存每个对话最近 10 轮，并在重新连接、前台恢复和进程重启后同步
- 开启任务完成、失败、等待审批和等待回答提醒，点击通知进入对应对话或待处理项

新建首轮按用户确认的方式携带路径及 Skill 引用。已有对话使用原生结构化输入，尚未载入时会打开对应桌面对话。对话引用提供发送准备时的公开用户与助手消息快照。

Android 提醒需要通知权限，开启后显示常驻连接通知。断线事件在重新连接后补收，系统省电或主动停止应用可能延迟到达，重新打开应用后恢复。原生 HTML／PDF 阅读、后台与锁屏提醒、断网补收及强停后重新打开均已通过 Android 16 模拟器检查。系统文件选择与保存、Tailscale 实际网络及手机省电设置仍需真机验收。仅有桌面媒体 `fileId` 的图片会显示当前读取限制。

`0.2.1` 修正刷新按钮的触屏悬停外观，并显示刷新中、完成时间和失败状态。聊天页使用一个顶部栏展示会话标题、目录、模型、状态和设置入口。连接中断后显示重连提示，自动重试期间可立即重连。设置页的返回按钮和 Android 系统返回均回到原页面，保留当前对话、滚动位置和草稿。历史响应缺少标题时保留已有标题，修正 SQLite 非空约束错误。

`0.2.2` 使用固定签名生成 APK，支持后续覆盖安装。历史改为通过 App Server 按条目分页读取，单轮内的消息可继续向前加载。当前对话读取失败时显示独立错误和重试入口，并检查服务连接。顶部显示连接状态，设置和刷新使用图标，刷新期间图标旋转。设置页的返回入口统一放在左上角，同时支持 Android 系统返回键。

`0.3.0` 完成第一批任务操作。新建会话支持项目、模型及思考深度选择，默认沿用 Codex 设置。已有会话可保存手机端下一轮发送参数，执行中追加沿用当前轮次。停止请求携带预期轮次 ID，轮次切换时返回未命中结果并重新读取状态。新建和停止请求与发送记录一样持久化，保留结果不确定时的核对入口。

首次读取、补齐最新消息和读取更早消息均有独立状态。分页请求的忙碌状态持续到请求结束，执行提示和停止入口依据本次实时状态。过期请求的成功、失败及收尾均检查归属，较旧历史响应无法覆盖已接收的新实时内容。

`0.4.0` 完成第二批交互接入。审批保留原始请求标识及数据类型，按命令、文件、权限、普通问答和 MCP 请求分别提交。已结束的请求由电脑端重新校验。发送结果不确定时保留操作记录，恢复页面后继续查询原回执。异步问题支持逐题回答及修改，发送中的答案跨进程恢复，普通输入草稿独立保留。

`0.4.0` 的 Skill 列表来自当前项目目录，选择仅用于本次发送。该版本在会话未加载时提供「在电脑端打开对话」入口，首条消息创建后可为后续发送选择 Skill。编辑仅用于最近一条原生用户消息，电脑端重新核对完整历史及运行状态，并保留原有附件和权限设置。

标准 MCP 表单支持基础字段及枚举，URL 请求先打开 HTTPS 页面，再由用户确认继续。身份验证及无法完整展示的特殊表单显示公开说明，由电脑端完成。未提交的请求表单在同一聊天的实时刷新、断线和设置页返回期间保留。切换到其他聊天后重新读取请求。

`0.5.0` 接入第三批会话组织和附件操作。置顶直接同步桌面侧栏，列表先显示已置顶对话。完整历史分支沿用原工作目录，创建请求使用持久回执去重。分支已经创建而历史同步失败时保留新会话入口，供用户核对。

消息的「引用」入口默认带入整条正文，选中文字后点击可只带入选中部分。确认后追加到当前草稿，并记录来源对话和消息标识。当前版本跳过原生 `Ask in side chat`，不增加「引用到新对话」替代入口。

附件选择支持电脑文件、电脑文件夹和手机文件上传。手机上传文件保存在服务数据目录的 `uploads` 子目录，每个文件使用独立目录保留原文件名。单个上传文件和图片预览上限为 20 MiB，电脑文件及目录引用传递绝对路径。附件选择跟随聊天草稿保存，投递成功后清除本次选择。会话尚未载入桌面时，先点击「在电脑端打开对话以发送附件」，该操作会切换电脑当前页面。

文件和目录使用 Codex 原生附件上下文，图片同时传递原生图片输入。原生编辑保留已有附件。图片预览通过认证 API 按需读取，手机端缓存保存附件路径及消息中已有的图片数据。

当前桌面原生编辑接口会把正文中的 `## My request:`、`## My request for Codex:` 当作上下文分隔标记。此类消息仍可正常阅读和引用，编辑窗口显示限制原因并保留草稿，用户可另发修正消息。

## 电脑端服务

从 Actions 下载 Windows 服务包，解压后保留可执行文件和同目录的 `web` 文件夹。首次使用时，用已授权作为手机入口的 Codex 聊天 ID 初始化配置。

```powershell
.\codex-reach-server.exe --init=来源聊天ID
```

配置保存在 `%LOCALAPPDATA%\CodexReach\server.json`，其中的访问密钥由程序生成。`CODEX_REACH_HOME` 可以指定独立运行目录。

保持 Codex 和 Tailscale 运行，查询电脑的 Tailscale IPv4 地址。把下面示例中的 `100.64.0.1` 替换为该地址后启动服务。

```powershell
tailscale ip -4
.\codex-reach-server.exe --listen=127.0.0.1:4317 --listen=100.64.0.1:4317
```

也可把监听地址写入 `server.json` 的 `listen` 数组，之后直接启动程序。服务默认监听 `127.0.0.1:4317`。

本机后台部署已添加当前用户的登录启动项，在 `shell:startup` 中显示为「Codex Reach」。程序与 `web` 放在 `%LOCALAPPDATA%\CodexReach\app`，配置和发送记录仍保存在原运行目录。启动脚本 `start-server.ps1` 位于配置目录，隐藏运行，等待配置的监听地址可用后启动服务；启动器退出后服务继续运行，重复启动不会增加服务实例。

Codex 已有当前用户登录启动项，Tailscale 使用自动启动的系统服务。手动启动时可运行「Codex Reach」启动项，取消自动启动时删除该快捷方式。服务输出保存在 `%LOCALAPPDATA%\CodexReach\server.stdout.log` 与 `server.stderr.log`，启动器状态保存在 `startup.log`。更新电脑端时先停止服务，再覆盖 `app` 中的程序与 `web`，随后运行启动项。

在电脑浏览器打开 `http://127.0.0.1:4317/setup`，查看手机使用的服务地址并复制访问密钥。该配置页面校验本机来源与 Host，聊天 API 使用 Bearer 密钥认证。

服务连接当前用户的 `codex-app-tools-*` 和 `codex-ipc` 命名管道。工具管道提供项目、会话、新建以及向未加载会话投递消息的入口。历史读取使用 `codex app-server --stdio` 的 `thread/read` 和 `thread/items/list`，每页 100 个条目，并通过同一读取会话查询模型目录。消息继续由桌面客户端执行。IPC 提供实时快照、版本化增量、参数更新、发送、停止、审批和原生编辑入口，手机实时响应保留最近 10 轮内的最后 100 条可显示消息。当前适配核对版本为 Codex Windows `26.1106.6628.0`，电脑须能执行 `codex` 命令。

## 手机端

1. 连接与电脑相同的 Tailscale 网络
2. 安装 Actions 产物中的 APK
3. 填写 `/setup` 页面显示的服务地址与访问密钥
4. 选择项目或对话，读取历史并发送消息

每条发送使用独立请求 ID。服务先将请求保存到本地 SQLite，再投递给桌面。相同 ID 的重复请求返回已有结果。连接中断或服务退出导致结果不确定时，界面保留草稿并提示核对聊天记录，由用户确认后恢复编辑。

验证包的 applicationId 为 `io.github.dengjiajun.codexreach.verification`。从 `0.2.2` 起，CI 使用固定 PKCS12 签名，后续版本可以覆盖安装并保留应用数据。`0.2.1` 及以前使用临时签名，首次切换需要卸载旧包，卸载会清除手机端缓存和草稿。

固定签名由仓库 Secrets 中的 `ANDROID_SIGNING_KEYSTORE`（PKCS12 文件的 Base64 内容）和 `ANDROID_SIGNING_PASSWORD` 提供，别名为 `codex-reach`。本机另有签名文件和口令备份。构建产物的 `signing.txt` 保存公开证书指纹。手动触发工作流时，可填写先前固定签名构建的 `upgrade_run_id`，验证证书一致、覆盖安装成功，以及数据库在更新后保留。

## 验证

2026-11-11 的 `0.1.0` 验证包已通过 GitHub Actions 的 Android 16 x86_64 模拟器检查，以及 REDMI K80 Pro、Android 16 真机检查。真机批量写入 1000 条合成消息耗时 129 ms，连续读取两页历史耗时 2 ms，保存数据再次读取耗时 20 ms，两次数据标记一致。[初始 CI 验证记录](https://github.com/Deng-Jiajun/codex-reach/actions/runs/42858452985)

`0.2.0` 的 Windows 服务已在本机完成项目和会话查询、真实桌面对话收发、相同请求重复提交验证。执行中追加的输入已进入同一轮，页面发送取得预期回复。服务重启后发送记录保留，页面自动重连并保留草稿。Android 的网络交互和离线缓存由工作流中的合成服务检查，实际手机网络连通与交互需在安装后核对。

连接页保留「SQLite 检查」入口，覆盖以下内容。

- 从 WebView 通过 Capacitor 调用 Android SQLite 插件
- 批量写入 1000 条合成消息，按会话分页读取
- 在同一事务中替换最新轮次并保存同步位置
- 写入中途触发主键冲突，检查消息与同步位置均已回滚
- 关闭并重新打开连接后读取数据
- 在 CI 中停止应用进程，重新启动后核对消息、同步位置和持久化标记
- 检查 APK 签名、ZIP 16 KB 对齐和 64 位原生库的 ELF 加载段对齐

工作流还检查错误密钥、项目与会话加载、HTTP 消息发送、实时回复、Markdown 清理，以及强行停止进程后在离线状态读取聊天缓存和草稿。交互回归覆盖刷新图标旋转、设置页左上角与系统返回、重新连接原会话、列表与聊天的断线恢复、单个会话读取失败时仍显示已连接，以及空标题响应的缓存保存。Windows 服务执行 Rust 单元测试，并构建可执行文件。

第一批任务回归加入可控的首次读取与分页延迟，在分页期间推送实时更新，检查加载提示、按钮状态和请求次数。另检查模型与深度联动、新建请求去重、过期轮次停止、当前轮次停止，以及下一轮实际提交的参数。本机已通过真实桌面创建、模型与深度生效、首条消息显示及轮次中断验证。

第二批回归覆盖审批原始 ID 类型及重复提交、完整权限和 MCP 字段、问答表单草稿与焦点、发送中断后的答案恢复、Skill 选择持久化及发送后清除，以及编辑替换回复时保留普通草稿。本机已验证真实桌面原生编辑，并在历史输入中核实 Skill 的名称和路径。

## 本地开发

```sh
npm ci
npm run dev
```

浏览器可预览页面。原生 SQLite 检查在 Android APK 内运行。

```powershell
cargo test --manifest-path server/Cargo.toml --locked
cargo run --manifest-path server/Cargo.toml -- --web-dir=dist
```

```sh
npm run android:sync
```

该命令构建 H5 并同步 Android 工程。安装包由 Actions 中的 `Android verification` 工作流生成。Android SDK、JDK 和 Gradle 构建环境由 CI 提供。

## 安装验证包

1. 打开 Actions 中成功完成的 `Android verification` 运行
2. 下载 `codex-reach-verification-运行编号` 产物，解压取得 `app-debug.apk`
3. 安装 APK，从连接页打开「SQLite 检查」，点击「运行全部检查」，确认全部通过并记录数据标记
4. 在系统设置中强行停止应用，重新打开后点击「检查已保存数据」，确认检查通过且数据标记一致

当前 CI 使用 Android 16 x86_64、4 KB 页大小的模拟器。16 KB 页大小环境的运行验证待完成，静态对齐检查结果可在产物中查看。

## 数据与配置

验证数据库使用合成数据。实际聊天缓存保存在手机应用目录，服务配置和发送记录保存在电脑的运行目录。仓库忽略数据库文件、`.env`、日志、keystore 和构建产物。Android 关闭 Capacitor 调试日志，服务日志只记录启动地址和运行错误。
