# Codex Reach 产品规格

更新日期为 2026-11-14。本文记录当前有效需求与验收要求。方案依据及修订过程见 [决策记录](决策记录.md)，安装与使用见 [README](../README.md)。

## 当前范围

手机通过 Tailscale 连接电脑上的 Reach 服务，查看和操作现有 Codex App 的同一批项目与对话，任务继续由电脑执行。主要使用设备为 REDMI K80 Pro、Android 16。

2026-11-13 用户确认项目自用，`0.6.0-preview` 起支持 Android 13 及以上，以 Android 16 为主要验收环境。原生能力选型使用这一支持范围内的特性。

当前方案为 Rust 本地服务、H5 界面、Capacitor Android APK 和原生 SQLite。项目名为 Codex Reach，仓库名为 `codex-reach`，使用公开 GitHub 仓库。访问凭据、签名私钥、真实聊天数据和本机运行配置保存在仓库外。

当前版本为 `0.6.2-preview`，Android `versionCode` 为 12，包含下述 0.6.1 真机反馈与复核修正。APK 和 Windows 服务包已构建，固定签名与 0.6.1 一致，覆盖安装、SQLite 数据保留和 14 项 Android 16 模拟器回归通过，真机验收待用户完成。[0.6.2 CI](https://github.com/Deng-Jiajun/codex-reach/actions/runs/43575447611)

2026-11-13 完成本轮规格审定。用户确认加入任务提醒、只读改动审阅、运行中消息排队与立即追加，以及消息复制、阅读定位、归档恢复和文件保存，分批实施。用户随后补充对话列表按状态、项目和时间切换分组。本轮实现及验证结果见下文。

## 功能与行为

| 功能 | 当前有效要求 |
| --- | --- |
| 服务启动 | 当前用户登录 Windows 后隐藏启动，等待配置的监听地址可用；启动器退出后服务继续运行，Codex 与 Tailscale 保持运行 |
| 连接 | 明确显示连接状态，断线自动重试，并提供立即重连入口 |
| 项目与对话列表 | 项目筛选及日期、项目、状态分组集中在顶部「⋯」菜单，搜索图标按需展开搜索框，搜索已加载标题与项目；同一目录的项目 ID 和无项目记录合并分组，异路径同名项目显示路径区别；每条对话单行显示 |
| 新建对话 | 选择项目或独立目录、模型和思考深度，提交首条消息时创建；首条消息携带完整附件、Skill 和引用，沿用统一输入交互 |
| 置顶 | 与桌面侧栏同步，列表优先展示置顶对话；列表通过长按菜单设置或取消，对话内通过「⋯」操作，已置顶状态使用低权重静态标记 |
| 消息 | 发送，执行中显式选择立即追加或排队到下一轮；中间进度、公开思考摘要和工具记录合并折叠，最终回答保持展开；保留输入草稿 |
| 模型与思考深度 | 作为基本参数提供直接入口，深度选项随模型变化；明确展示当前会话参数与下一轮选择的适用范围 |
| Skill | 在输入框中通过 `@` 触发当前项目可用 Skill 的候选列表，选择用于下一次发送，成功投递或保存到电脑队列后清除本次选择 |
| 停止 | 与发送共用输入区右下角按钮，运行中且无可发送内容时显示停止图标；针对当前正在执行的轮次发起停止，轮次变化后重新读取状态 |
| 编辑 | 编辑最近一条原生用户消息，重新执行并同步被替换的回复，保留原有附件与普通输入草稿 |
| 审批与问答 | 手机处理命令、文件、权限审批、普通问题及可完整展示的标准 MCP 表单 |
| 添加到对话 | 选择回答片段并附上意见，以卡片保存原文、意见和来源位置；与当前输入草稿一同发送 |
| 附件 | 浏览电脑文件与目录，上传手机文件，发送附件；正文显示缩略图或文件摘要，完整路径在详情中查看 |

「创建完整历史分支」按本次明确要求移除。`Ask in side chat` 已确定跳过，「引用到新对话」替代入口也已排除。用户通常通过直接向 Codex 表达需求来发起相关新对话。

### 参数生效规则

`0.5.0-preview` 的已有行为如下。

- 新建对话可以使用 Codex 默认参数，也可以选择模型与思考深度
- 已有对话在手机保存下一轮发送参数，发送时应用
- 执行中追加使用当前轮次参数

本轮参数选择沿用下一轮发送时应用的规则。队列项保存其正文、上下文和下一轮参数，实际投递前校验可用性。执行中立即追加沿用正在运行的轮次参数。

### 身份验证与编辑边界

普通 HTTPS 授权链接已有手机打开入口。依赖桌面专用服务的身份验证，以及手机无法完整展示的特殊表单，显示具体说明并交由电脑处理。

当前桌面原生编辑接口将正文中的 `## My request:` 和 `## My request for Codex:` 作为上下文分隔标记。命中该限制的消息显示编辑限制原因并保留草稿，阅读与选段功能继续可用。包含选段上下文的消息也需按该限制处理，该限制随桌面接口适配情况复核。

## 界面与状态

整体采用简洁的浅色界面，以 Qoder 移动端截图为主要参考，保证正文、点击区域和常用操作适合手机。模型参数、任务设置与消息操作的参考方案见决策记录。

- 聊天标题、项目或目录信息、运行状态和设置入口集中在一个顶部栏
- 首页仅保留一行「对话」工具栏，连接状态、搜索、新建及「⋯」位于同一行；首页与聊天的连接设置均从「⋯」进入
- 下拉刷新提示随手势展开，达到触发距离后提示松开，刷新期间显示动态加载图标，结束后收起；列表「⋯」保留手动刷新入口
- 设置页保留左上角返回，弹层提供关闭入口并支持点击背景空白关闭，Android 系统返回按当前层级处理
- 返回设置前的页面时保留当前对话、草稿和阅读位置
- 首次读取、同步最新消息、加载更早消息分别反馈进度，已有内容在同步期间继续可读
- 单个对话历史读取失败时显示该对话的错误与重试入口，连接状态按实际连接结果显示
- 页面和所有弹窗避让系统状态栏与底部手势区域，内容超长时可滚动并能到达确认操作

| 状态或提示 | 含义与显示要求 |
| --- | --- |
| 已连接、重连中 | 手机与电脑服务及桌面连接的实际可用状态 |
| 正在读取对话 | 首次读取历史 |
| 正在同步最新消息 | 已有内容的最新状态同步 |
| 读取更早消息的加载反馈 | 分页请求仍在进行，忙碌状态持续至请求结束 |
| 进行中 | 当前对话正在执行任务，列表及聊天顶栏使用动态旋转图标，保留可访问名称 |
| `idle` | 内部空闲状态，列表和聊天页均隐藏该标签 |
| 等待处理请求 | 存在需要用户审批或回答的请求 |
| `notLoaded` | 内部执行实例的加载状态，用户界面隐藏该值；历史可读性由历史查询结果判断 |

「未加载」此前因作用不明已去掉。本次曾提出重新显示，用户已再次纠正，该显示已撤回。用户随后确认去掉「空闲」。列表和聊天页隐藏 `idle` 与 `notLoaded`，任务执行、待处理请求和异常继续明确反馈；历史读取失败另行提示。

### 2026-11-13 已确认的阅读与传输需求

以下需求由 `0.6.0-preview` 实现，历史版本的验收记录保留其对应版本。

- 普通网页和电脑本地 HTML 默认在应用内半屏阅读面板打开，支持上拉全屏及可见的展开、关闭操作。关闭后恢复原聊天位置和输入草稿
- 首批本地阅读覆盖 HTML、Markdown、文本／代码、图片和 PDF。消息里的电脑文件链接、附件条目和文件浏览入口进入对应阅读器
- 助手回答中的示意图、截图等图片在正文对应位置直接显示，保留图文顺序和比例，点击可放大阅读。图片加载失败时显示可辨识的占位与重试入口
- 正文中的电脑图片路径经已鉴权的图片读取能力取得内容，网络图片与桌面原生图片内容按实际来源适配。历史加载、实时更新和缓存恢复都应保留图片引用，原生图片产物的数据格式在实现时核对
- HTML 阅读包含相对图片、CSS 和脚本。电脑路径按文件引用处理，资源加载需要经过电脑服务授权，预览页面与主应用凭据分离
- 文件名或网页域名显示在阅读面板顶部。文件不存在、加载失败或格式暂不可读时说明原因，并提供适用的重试或文件操作
- 上传与下载采用有收益的无损传输压缩，解压后交给 Codex 或保存的文件字节与原文件一致。传输量、端侧耗时和内存开销分别验证
- 使用按项目适配的 `codex-reach-mobile-ux` skill，设计与验收覆盖手机触摸、键盘、滚动、系统返回、草稿和应用内阅读

### `@` 引用

用户确认 `@` 入口同时支持 Skill、项目文件和对话，适用于新建及已有对话的输入区。候选按类型区分并支持关键词筛选，选择后保留稳定标识和可读名称，随当前草稿保存。

输入 `@` 时触发候选，新建、已有对话和队列编辑共用该方式。

- Skill 显示名称与简短用途，按当前工作目录查询有效项目能力
- 项目文件显示名称与项目相对路径，发送时复用文件引用能力，点击可进入文件阅读
- 对话显示名称、所属项目等辨识信息，引用保存真实对话标识。发送时提供该对话公开用户与助手消息的上下文快照
- 未选择候选时，输入内容作为普通正文保留。已选引用支持查看和移除，对话重命名后仍按真实对话标识定位；文件移动或改名后提示重新选择
- 引用操作归属于当前输入草稿，消息发送目标保持为当前正在编辑的对话

新建首轮通过桌面 `create_thread` 的正文携带文件路径、图片路径及 Skill 名称和路径。该方式已经用户确认，图片由模型读取工具查看。已有对话使用原生结构化文件、图片和 Skill 输入，未载入时先打开桌面对话并等待执行端就绪。创建结果通过稳定请求标识保存和查询，结果未知时保留草稿。

对话引用按真实对话 ID 读取发送准备时的用户与助手公开消息，保存为电脑上的 JSONL 上下文文件并随附件提供。文件记录对话名称、ID、目录和轮次来源。真实首轮及队列测试已确认模型能够读取文件、Skill 和所引用对话中的标识。

### 0.6.0 真机反馈修正

2026-11-13 用户补充首页、长按菜单、聊天输入区、发送方式、权限设置和阅读定位截图，以下要求替代早期实现中的对应布局。

- 首页常驻一行对话工具栏，搜索通过图标展开，项目筛选位于「⋯」菜单
- 按项目分组统一识别项目 ID 与对应目录，Windows 盘符路径统一分隔符、尾部分隔符和大小写。同名异目录项目通过路径辨识
- 弹层右上角提供关闭图标，点击弹层外空白和系统返回可关闭当前层，内部点击和从内部拖出保持当前弹层。关闭后保留原阅读位置与输入草稿
- 长按对话菜单使用图标及动作名称，消息复制、编辑、输入展开和收起使用有可访问名称的图标按钮
- 输入框采用上方正文、框内底部工具栏，内容超过普通高度上限后才显示右上角展开。添加、模型与深度、共用的发送／停止集中在工具栏，新建与已有对话使用同一布局
- 运行中的发送方式由发送按钮旁的下拉图标打开紧凑面板，明确「立即追加」与「排队到下一轮」的用途，发送图标随选择更新。待发队列通过带数量的图标进入
- 「回到最新」在聊天内容右下角悬浮显示下箭头，离开底部时出现，回到底部后隐藏，显隐时阅读区高度保持稳定

权限模式显示「请求批准」「自动审批」「完全访问」，附桌面英文名称和用途说明。保存时同时设置权限范围、审批规则与审批者，检查电脑的允许配置和自动审批关闭状态。完整组合无法识别时显示「当前自定义权限」，保留原设置直至用户选择替代模式。仅修改模型和深度时保留当前权限。

本轮修正由 `0.6.1-preview` 交付。前端 21 项测试、Rust 44 项测试、前端构建、浏览器合成回归及 Android 16 模拟器回归通过，Android 真机及真实桌面权限写入待验收。

### 0.6.1 真机反馈修正

2026-11-14 用户确认以下交互要求，替代上述旧版对应行为。本次修正由 `0.6.2-preview` 交付，真机验收待用户完成。

- 发送与停止共用右下角按钮。有文字、附件、Skill、对话引用或选段时显示发送图标；运行中且内容为空时显示停止图标，空闲且内容为空时禁用发送。上传期间保留发送状态并禁用，运行中有内容时提供追加／排队菜单
- 首页以「对话」作为单行顶栏标题，连接设置合并到首页及聊天的「⋯」菜单。刷新提示随下拉距离展开，松开触发后转为加载动画，取消、未达到距离或请求结束后收起
- 对话名称显示时合并空白，超过 60 个 Unicode 字符时省略。长按菜单标题与引用候选标题最多显示两行，完整原始标题继续用于搜索与改名编辑
- 同步问答和异步问题均可直接点击或输入自定义回答，自动选中对应分支。切回选项后按选项提交，自定义草稿继续保留，未提交及提交中状态沿用原请求规则
- 列表和聊天顶栏中的「进行中」使用动态旋转图标，保留可访问名称；待处理和异常继续显示各自状态

本阶段前端 22 项测试、构建及浏览器手机尺寸回归通过。浏览器覆盖触摸下拉、取消与收起、发送／停止切换、停止请求、同步及异步自定义答案提交、长标题和窄屏布局。Android 回归入口同步后随 `0.6.2` 通过模拟器检查，真机验收待执行。

### 0.6.1 后续整体设计复核

2026-11-14 用户补充添加内容缺少图标、发送按钮占用过大、短输入仍显示展开、附件逐行堆叠、空队列常驻，以及中文文档和带行号源码无法打开。复核结论是输入、附件与阅读器缺少统一的内容层级、按需显示和操作布局，不能仅凭局部按钮修正判定符合手机使用要求。

| 范围 | 统一规则 |

## 对话组织与阅读定位

### 列表分组、排序、筛选与状态

列表顶部「⋯」菜单提供「分组方式」，包含「日期」「项目」「状态」三个选项，并标明当前选择。页面常态展示分组后的单行对话列表，切换入口集中在菜单内。保存用户选择，首次默认按日期分组和最近活动时间倒序排列。搜索、项目筛选与分组可以组合使用。置顶对话在各方式中优先展示，其余顺序遵循所选分组。

每条对话占一行，标题与未读、运行、置顶等必要标记处于同一行。长标题省略显示，项目、目录和完整时间在分组标题或详情中查看，必要的简短日期使用同一行右侧的低权重文字。

置顶操作按用户最新决定集中到列表长按菜单和对话内「⋯」。已置顶对话可显示尺寸较小、颜色较弱的静态标记，标记本身作为状态提示。未置顶对话以普通标题展示。

| 分组方式 | 组内与组间顺序 |
| --- | --- |
| 日期 | 按日期分组，组内按最近活动时间倒序 |
| 状态 | 待处理或异常优先，其次执行中、等待其他对话、其他对话；同组按最近活动时间倒序 |
| 项目 | 按项目分组并按项目名排列，独立目录显示可读目录名，组内按最近活动时间倒序 |

状态分组只使用已核实的数据。运行、未读和置顶分别保存，列表继续遵守隐藏 `idle` 和 `notLoaded` 标签的决定。桌面 recent 提供的 `isUnread` 按对话 ID 合并，history 缺少该字段时保留未知状态及已知值。打开缓存、停留在旧历史或同步失败时保留未读标记，最新内容成功展示且用户到达底部后再更新已读状态。

列表变化采用可核实的摘要事件或受控刷新，覆盖打开列表、前台恢复和操作成功后的同步。当前对话的实时更新与全局列表同步分别验收。

### 查找、复制与最新内容

- 支持复制消息正文和单独复制代码块，保留代码的换行与缩进，给出操作反馈
- 用户阅读旧消息时保留当前位置，新内容和待处理请求出现后提供「回到最新」或「查看待处理」入口
- 列表标题搜索与对话内查找均显示实际搜索范围。当前已加载内容可先检索，继续读取历史时提供加载进度，结果展示准确来源并支持定位
- 归档将对话移至归档列表，保留历史并支持恢复，结果与桌面同步
- 永久删除移除对话记录，并按桌面规则级联删除子对话和附属对话。操作前显示对话名称及根据桌面关联关系计算的影响范围，由用户确认
- 对话组织与上传文件清理分别执行。删除或归档成功后同步当前页面、列表和相关缓存

## 最终对照补充的功能

### 任务提醒

对任务完成、失败、等待审批及等待回答提供可配置提醒，点击定位到对应对话或待处理项。前台阅读历史时也能发现待处理状态，同一事件按稳定标识去重。通知权限由用户开启。

手机后台及锁屏提醒需要实际的 Android 事件接收方案，结合现有 Tailscale 与电脑服务验证。验收区分前台、后台、锁屏、断网恢复和进程终止。本轮实现使用 Android 原生前台服务独立接收提醒，手机页面的长轮询仍按前后台状态管理。用户开启提醒并授予通知权限后启动接收服务，系统通知持续显示连接状态。电脑持久保存事件，手机按游标补收，稳定事件标识用于去重。涉及额外外部推送服务或账号时，先说明具体依赖与数据范围，再由用户决定接入方式。

### 改动文件与只读 diff

提供改动文件列表与差异阅读，显示文件路径、增加／删除／修改状态，并支持打开源文件。差异标明所属轮次、对话或工作区比较范围。读取真实桌面变更数据或对应 Git 比较结果，并区分任务变更与工作区既有改动。

文件变更审批中的差异继续展示。任务结束后的改动审阅也有入口，二进制或无法取得差异的文件显示具体状态。首批实现只读审阅，用户可通过现有选段意见流程提出修改要求。

### 立即追加与排队到下一轮

正在执行时，发送控件明确展示「立即追加」与「排队到下一轮」。默认沿用现有立即追加行为，用户可选择排队。队列项保存正文、附件、Skill、引用及参数，支持查看、编辑和取消，开始投递前保留在待发区域，成功后进入已发送历史。

优先核对桌面原生队列能力，投递使用稳定操作标识。需要本地队列时由电脑服务持久保存，并核对桌面轮次状态、重试和并发。手机切后台或重启后可以恢复队列状态，发送结果未知时先查询原操作结果。界面区分等待投递、投递中、已接收和失败。

### 文件保存

电脑文件、图片和生成物提供保存原文件到手机的入口，显示名称、大小、下载状态与失败重试。保存后可由用户主动调用系统分享。HTML 的原文件下载与应用内包含相对资源的阅读分别标明，完整资源包分享后续按实际需要确定。

## 历史缓存与同步

用户要求已看过的对话能够快速恢复，避免每次打开都重新等待全部历史。采用原生 SQLite，支持缓存读取、分页和事务保存。最近一轮可能因误发送后编辑而改变，包括已经结束的轮次，编辑后的整轮结果需要重新同步。

同步与数据处理需要覆盖以下行为。

- 先显示已有缓存，再获取最新内容
- 历史分页读取，长对话能够继续向前加载
- 手机切后台、网络恢复和应用重启后重新同步当前对话，保留草稿
- 编辑或回退后，根据轮次和消息身份替换受影响内容，迟到响应按请求归属处理
- 消息与同步位置在同一事务中保存，发送请求用稳定标识查询原操作回执
- 减少重复传输和大对象处理，基本属性查询避免受正文读取拖累

当前实现保留每个已缓存对话最近 10 轮，历史接口每页读取 100 个条目，实时响应限制在最近 10 轮内的最后 100 条可显示消息。这些数值属于现有实现参数。真实长对话的首屏、翻页、编辑后恢复和持续更新性能仍需验收。

桌面实时流已核实存在 `baseRevision/revision`，用于判断增量连续性。持久消息的逐条编辑版本号尚无已确认依据，历史同步应依据已核实接口。手机与服务之间当前采用有限范围的实时快照，原方案中“只传新增文本”的性能目标仍需按实际实现复核。
