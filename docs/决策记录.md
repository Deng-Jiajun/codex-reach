用户在 0.6.0 真机截图中指出同一 pc 项目重复分组、首页筛选重复占行、弹窗缺少关闭、输入区偏离示意图，以及消息操作、运行中发送和回到最新的入口不合适。

弹层统一右上角关闭、背景空白关闭和系统返回。关闭判断要求按下与释放都位于弹层之外，避免内部滚动拖出时误关。长按菜单使用图标及名称，复制、编辑、展开与收起使用图标。输入区按原示意图把正文与底部工具栏放入同一个圆角容器，新建对话沿用这一结构，`@` 由输入触发。

运行中追加和排队通过发送旁的紧凑面板切换，明确每种行为的生效时点，队列图标显示待发数量。回到最新改为聊天内容上的悬浮下箭头。

用户补充桌面权限菜单截图后，确认原手机实现只修改底层 approvalPolicy，缺少权限范围和审批者。现场核对安装包的模式目录、设置更新入口及 ThreadSettingsUpdateParams schema 后，按下表同步读取与写入。

| 模式 | permissions | approvalPolicy | approvalsReviewer |
| --- | --- | --- | --- |
| 请求批准 / Ask for approval | :workspace | on-request | user |
| 自动审批 / Approve for me | :workspace | on-request | guardian_subagent |
| 完全访问 / Full access | :danger-full-access | never | user |

当前桌面同时识别 auto_review 与 guardian_subagent，写入沿用该桌面版本模式目录使用的值。设置更新使用 IPC 版本 2，省略 activeTurnId，生效于后续轮次。permissions 由桌面解析为权限 profile，更新接口禁止同时传入 sandboxPolicy。

读取保留自定义 profile 和 granular policy，保存其他参数时保留原权限。旧 APK 的 policy 请求继续按原字段语义处理，新界面使用 mode 请求。服务在读取和保存时核对 allowedPermissionProfiles、allowedSandboxModes、allowedApprovalPolicies、allowedApprovalsReviewers，自动审批还检查项目有效配置中的 guardian_approval 明确关闭值。桌面远端功能开关的可读接口尚未确认，实际写入错误由手机呈现。[官方权限说明](https://learn.chatgpt.com/docs/permission-modes)

本次浏览器合成检查覆盖目录分组、图标、背景关闭与拖出、输入光标与草稿、`@`、排队投递、权限模式显示与保存、悬浮回到底部、窄屏、横屏、缩短视口和安全区。前端 21 项测试及 Rust 44 项测试通过。缩短视口用于检查布局，真机软键盘、系统返回及覆盖安装仍需新 APK 验收。真实桌面权限写入尚未执行。

用户随后授权提交推送并构建 `0.6.1-preview`。首轮 Android 回归沿用「标题栏第一个按钮」定位关闭，布局调整后点到了展开按钮。改为按关闭控件定位后，完整 CI 通过，固定签名、从 0.6.0 覆盖安装及 SQLite 数据保留验证完成。构建提交为 `f08f929`，真机交互及真实桌面权限写入继续列为待验收。[0.6.1 最终 CI](https://github.com/Deng-Jiajun/codex-reach/actions/runs/43494540079)

### 文件传输与本地阅读

用户在 `0.5.2` 手机上反馈回答中的两张界面示意图缺失，同一回答在桌面 Codex App 可以显示。源码核对发现 `src/main.ts` 的 Markdown 清理规则显式移除 `img`。本次示意图引用电脑上的 PNG 路径，手机还需要通过已鉴权的内容接口取得图片字节。将回答正文图片显示加入下一轮阅读能力，按原位置保留图文顺序，并覆盖历史、实时和缓存恢复。

用户将压缩要求明确为传输过程中的无损压缩。六张授权 JPG 在本机内存中经 gzip level 6 测量，原字节合计由 3,306,455 B 减到 2,801,503 B，减少约 15.3%。同批文件的当前 Base64 JSON 上传体由 4,409,152 B 减到 2,804,025 B，减少约 36.4%。解压结果已逐字节核对，手机耗时与真实网络速度仍待实测。两项压缩收益分别基于不同的输入体积。

实现建议为文件二进制传输、上传请求解压和按客户端能力压缩响应。压缩收益、编码内存开销和原生网络行为需要结合当前 Capacitor 版本验证。

电脑路径阅读需要同时处理消息链接识别与文件内容服务。HTML 还需要加载同目录范围内的相对资源。网页半屏可评估官方 InAppBrowser 的 Custom Tabs，本地 HTML 则需要适合授权资源读取的独立阅读环境。预览页面通过专用内容通道取得文件，连接凭据由原生层或服务端持有。
